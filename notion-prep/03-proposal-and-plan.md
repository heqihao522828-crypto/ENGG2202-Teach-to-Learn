# Gate 03: Plan

## Decision

Which project route should the team pursue, and is it feasible to begin?

Gate 03 turns the validated problem into a justified plan. It is a design review, not a promise that every detail will remain unchanged.

## What to do

1. Compare buy, borrow, adapt and build options.
2. Convert stakeholder needs into testable requirements.
3. Draw the system architecture or workflow.
4. Define the smallest useful first version.
5. Prepare the budget, BOM, risks and schedule.
6. Assign responsibilities and create repository tasks.

## Project Approval Pack

Prepare one PDF containing:

1. one-page project canvas: problem, stakeholder, context, SDG target and success criteria;
2. concept comparison and selected route;
3. system architecture, CAD, block diagram or workflow;
4. requirements and test plan;
5. BOM, budget and sources;
6. schedule and team responsibilities;
7. main risks, safety controls and fallback plan;
8. repository link.

## Resources

| Need | Resource | Use it for |
| --- | --- | --- |
| Compare products and parts | Manufacturer datasheets and supplier pages | Check specifications, availability and cost |
| Find reusable designs | [GitHub search](https://github.com/search) | Compare open-source implementations and licences |
| Track the plan | GitHub Issues or Projects | Assign milestones, responsibilities and dependencies |
| Draw the system | Figma, diagrams.net, CAD or a suitable engineering tool | Keep an editable architecture or design source |
| Critique the plan | [HKU GenAI](https://genai.hku.hk/) | Find missing requirements, trade-offs and failure modes |

## Checkpoint submission

Submit the Project Approval Pack PDF and repository link through the route named by the teaching team.

## Ready for Gate 04

- The selected route is compared with alternatives.
- Requirements are measurable.
- The architecture and first version are clear.
- Cost, access, risk and safety are addressed.
- Tasks and responsibilities are visible in the repository.
