# Gate 04: Learn

## Decision

What can the team learn from existing work and a first working version?

Start by reproducing or studying relevant existing work. Build the smallest version that can test one important assumption.

## What to do

1. Find a relevant open-source project, published method, product or reference design.
2. Record the source, version, licence and parts your team may adapt.
3. Reproduce or inspect it before making major changes.
4. Open a GitHub issue for the learning question.
5. Build one small, traceable version.
6. Test the central assumption and ask another person to reproduce the setup.

## Minimum repository record

- current README and setup instructions;
- source and licence of adapted work;
- architecture or workflow;
- parts, dependencies and versions;
- build log with dated photos or screenshots;
- code, CAD or other editable source files;
- test method and observed result;
- failures, limitations and next question.

## Resources

| Need | Resource | Use it for |
| --- | --- | --- |
| Find existing open work | [GitHub search](https://github.com/search) | Identify projects to reproduce, study or adapt |
| Compare an external project pitch | [World Engineering Day and WFEO Hackathon](resources-world-engineering-day.md) | Notice how previous teams show development, testing and feasibility |
| Understand a repository or technical documents | [DeepTutor](https://github.com/Active-Learning-Kyle/DeepTutor) | Study selected repository files, papers or datasheets before changing the design |
| Repository workflow | [GitHub Issues](https://docs.github.com/en/issues/tracking-your-work-with-issues/learning-about-issues/about-issues) | Record learning questions, changes and failures |
| Student coding access | [GitHub Education](https://github.com/settings/education/benefits) and [Copilot Student guide](https://docs.github.com/en/copilot/how-tos/copilot-on-github/set-up-copilot/enable-copilot/set-up-for-students) | Apply separately for the student benefit and activate Copilot after approval |
| Explain unfamiliar material | [HKU GenAI](https://genai.hku.hk/) | Ask for explanations and code review that the team verifies |

DeepTutor and coding assistants are optional. The team must understand, test and explain any code or design it accepts.

## Controlled coding task

Give an AI coding tool one bounded task at a time:

> In this repository, implement [small task] within [files or module]. Keep [interfaces and constraints]. Add or update tests for [behaviour]. Before editing, explain the plan and list assumptions. Do not change unrelated files.

Review the diff, run the tests and record what the team accepted or changed.

## Checkpoint submission

Submit one team post on Ed Discussion with:

1. existing work studied or reproduced;
2. source, version, licence and attribution;
3. learning question;
4. first working version and setup evidence;
5. test method and result;
6. failure or limitation;
7. next change;
8. direct links to repository evidence.

## Ready for Gate 05

- Another person can inspect or reproduce the version.
- Adapted work is attributed and licence conditions are understood.
- The team can explain how the version works.
- At least one important assumption has been tested.
- Failures and limitations are recorded.
