# Gate 05: Improve

## Decision

What should the evidence make the team keep, revise or stop?

A demonstration shows that something happened once. A test uses a repeatable method to support a bounded claim.

## What to do

1. Write the decision the test must inform.
2. Define the input, conditions, procedure, measurement and expected result.
3. Preserve raw data before analysis.
4. Analyse variation, uncertainty and failure.
5. Select one meaningful revision.
6. Retest under comparable conditions.

## Resources

| Need | Resource | Use it for |
| --- | --- | --- |
| Analyse data | Python, Jupyter or a spreadsheet | Keep repeatable calculations, tables and plots |
| Learn from test documents and data notes | [DeepTutor](https://github.com/Active-Learning-Kyle/DeepTutor) | Review selected material, generate questions and compare interpretations |
| Review the test plan or code | [HKU GenAI](https://genai.hku.hk/) or Copilot Student | Find missing controls, edge cases and unsupported claims |
| Record iteration | GitHub Issues, commits and releases | Connect the failure, revision and retest |
| Compare local conditions | [DATA.GOV.HK](https://data.gov.hk/en/) | Use relevant public data when it supports the test context |

AI may review a method or help write analysis code. It cannot create measurements, remove inconvenient results or decide that a claim is proven.

## Checkpoint submission

Submit one team post on Ed Discussion with:

1. version and test question;
2. repeatable method;
3. raw data and analysis links;
4. result, uncertainty and failure;
5. revision selected from the evidence;
6. retest result;
7. claim the team can now make;
8. direct links to repository evidence.

Photos or video may show the setup and behaviour, but they do not replace the test record or raw data.

## Ready for Gate 06

- The test can be repeated.
- Raw data and analysis are preserved.
- The revision follows from evidence.
- A retest shows what changed.
- Claims state their conditions and limitations.
